# 출력 방식 (인쇄와 PDF 저장)

## Decisions

- 인쇄와 PDF 저장은 모두 브라우저 인쇄 대화상자(`window.print()`)로 처리한다. 별도의 PDF 생성 라이브러리를 넣지 않는다.
- "PDF 저장"은 인쇄 대화상자에서 사용자가 "PDF로 저장" 대상을 고르는 것을 뜻한다.
- 인쇄용 지면 구성(A4 세로, 매 쪽 머리말, 필기 여백)은 인쇄용 CSS로만 만든다.

## Boundaries

- 매 쪽 자동 쪽번호는 이 방식으로 보장되지 않는다. 필요하면 인쇄 대화상자의 머리말·바닥글 옵션에 맡긴다.
- 나중에 뷰어나 리스트에서 인쇄하는 경우에도 같은 방식을 재사용한다.

## Why

강의용 학습 템플릿이고 동작하는 결과물이 우선이다. 클라이언트 PDF 생성은 지면 레이아웃을 따로 맞춰야 해서 범위가 커진다. 사용자는 한 번 클릭으로 파일이 떨어지는 것보다 대화상자를 한 단계 거치는 쪽을 받아들였다.

## Reconsider when

- 매 쪽 쪽번호나 정확한 머리말이 수용 기준이 되어 인쇄 대화상자로는 부족할 때.
- 뷰어나 리스트에서 여러 문서를 한 번에 PDF로 내보내야 할 때.

## Still-rejected alternatives

- Paged.js 등 페이지네이션 라이브러리 — CSS 카운터 기반 쪽번호·머리말은 되지만 슬라이스가 커지고 의존성이 늘어난다; 쪽번호가 수용 기준이 되면 재검토.
- 서버 사이드 PDF 렌더링 — 계정 없는 단일 페이지 도구에 백엔드를 들이게 된다; 보관 기능이 백엔드를 요구하게 되면 함께 재검토.
