# 02 — 저장 · 홈 목록 · 재열람 · 이어서 번역

## Outcome

번역 결과가 이 컴퓨터에 보관된다. 홈이 저장된 문서 목록이 되어 각 항목에 제목과
번역 진행 상태(번역된 문장 수 / 전체)가 보이고, 항목을 클릭하면 읽기 전용 2단
문서가 열린다. 저장된 문서를 다시 열면 재번역 없이 저장된 상태가 바로 보인다. 빈
우측 칸이 남아 있으면 "이어서 번역"으로 그 칸만 번역한다. 번역 중 정지하거나
페이지를 떠나도 그때까지의 번역이 저장된다. 파일의 URL이 이미 저장된 문서와 같으면
새 문서를 만들지 않고 그 문서를 연다.

## Blockers

01 — 저장하고 이어서 돌릴 번역 흐름이 있어야 한다.

## Acceptance criteria

- [ ] 번역을 일부 진행한 뒤 정지하거나 페이지를 떠났다가 다시 들어오면, 그 문서가 홈 목록에 있고 열면 번역이 그때까지 진행된 상태 그대로다.
- [ ] 저장된 문서를 홈 목록에서 다시 열면 재번역이 일어나지 않고 저장된 상태가 즉시 보인다.
- [ ] 빈 우측 칸이 남은 문서에서 "이어서 번역"을 누르면 빈 칸만 번역되고, 이미 번역된 문장은 그대로다.
- [ ] URL이 같은 파일을 다시 업로드하면 새 문서가 생기지 않고 그 저장된 문서가 열린다.
- [ ] 홈 목록 항목에 제목과 번역 진행 상태가 보인다.
- [ ] 목록에서 연 문서는 읽기 전용이다.

## Constraints

- 문서 식별은 파일의 URL 줄을 문자열 그대로 비교한다. 정규화하지 않는다.
- 같은 URL의 파일을 다시 올리면 기존 문서를 열고, 새로 올린 영어 본문은 무시한다.
- 저장 위치(브라우저 대 백엔드)는 구현 시 정한다. `PRODUCT.md`와 스펙은 이를 미결로
  유지하므로, 이 태스크가 고른 방식을 결정으로 굳히지 않는다.
- 진행 상태를 문장 단위로 저장할지 청크 단위로 저장할지는 재량이다.
- 출력·번역 방식은 01의 제약을 그대로 따른다.

## Verification

- 실제 앱에서: 파일 번역을 몇 문장 진행 → 정지 → 새로고침 → 홈 목록에 항목이 있고
  진행 상태가 맞다 → 열면 그 상태 그대로, 재번역이 시작되지 않는다.
- "이어서 번역"을 눌러 빈 칸만 채워지는지, 기존 번역이 유지되는지 확인.
- 같은 URL 파일을 다시 업로드해 그 문서가 열리는지(새 항목이 안 생기는지) 확인.
- `bun run test:e2e`로 저장 → 재열람 → 이어서 번역 경로. `bun run test` 통과.
