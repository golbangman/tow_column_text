# 01 — 영어 파일 업로드 → 문장별 번역 → 인쇄 (한 세션)

## Outcome

영어 자막 텍스트 파일을 올리면 영어가 문장 단위로 좌측에 놓인 2단 문서가 뜬다.
"번역 시작"을 누르면 문장을 하나씩 한국어로 번역해 우측을 위에서부터 채운다.
진행률(번역된 문장 수 / 전체)이 보이고, 정지할 수 있다. 정지하면 그때까지의 번역이
화면에 남는다. 한 문장의 번역이 실패하면 그 행의 우측은 비고 좌측 영어는 남으며 다음
문장으로 넘어간다. 완성했거나 일부만 된 문서를 브라우저 인쇄 대화상자로 인쇄하거나
PDF로 저장한다. 좌우 어느 칸도 편집할 수 없다.

진입점은 업로드 화면이다. 이 태스크는 지속 저장이 없다. 새로고침하면 사라진다.

## Blockers

None.

## Acceptance criteria

- [ ] 형식에 맞는 파일을 올리면 좌측에 영어 문장이 한 행씩, 우측은 빈 2단 문서가 나온다. 파일에 한국어 섹션이 있어도 무시된다.
- [ ] "번역 시작"을 누르면 우측 칸이 위에서부터 채워지고 진행률이 보인다.
- [ ] 번역 중 "정지"를 누르면 번역이 멈추고 그때까지 채워진 우측 칸이 화면에 남는다.
- [ ] 한 문장의 번역이 실패하면 그 행의 우측은 비고 좌측 영어는 남으며, 번역은 다음 문장으로 계속된다.
- [ ] 각 행에 문장 번호(1부터), 영어, 한국어 번역이 보인다. 그 행에 번역 결과가 나오면(전체 번역 중이라도) "다시번역"이 함께 보이고, 누르면 그 문장 하나만 다시 번역돼 그 행의 한국어가 갱신된다(이미 번역돼 있어도 덮어씀). 다른 행은 영향 없음. 문장 번호는 인쇄에 나오고 "다시번역"은 인쇄에 안 나온다.
- [ ] 좌우 어느 칸도 편집할 수 없다.
- [ ] 영어 마커가 없거나 순서가 뒤바뀐 파일, 또는 영어 본문이 없는 파일은 문서를 만들지 않고 기대 형식을 적은 안내문을 보여준다.
- [ ] 완성했거나 일부만 된 문서를 브라우저 인쇄 대화상자로 인쇄·저장할 수 있고, 지면은 A4 세로, 매 쪽 제목·URL 머리말, 2열, 필기 여백을 유지한다.

## Constraints

- 번역은 `docs/decisions/translation-method.md`를 따른다. 서버에서 headless 브라우저로
  `translate.google.com`을 조작해 문장을 하나씩 순차 번역한다. 좌측 문장 i가 우측
  번역 i와 짝이 된다. 여러 문장을 구분자로 묶어 한 번에 보내지 않는다.
- 파일 파싱, 문장 분리, 인쇄 지면 구현은 기존 `two-column-conversion` 구현의 코드를
  재사용한다. 마커는 공백과 등호 개수를 무시하고 인식한다. 파일의 한국어 섹션은
  무시한다.
- 편집 기능을 제거한다.
- 출력은 `docs/decisions/output-delivery.md`를 따른다. 이 태스크에서 다시 정하지
  않는다. 자동 쪽번호는 범위 밖이다.
- 번역 실행은 열린 페이지에 묶인다. 서버 백그라운드 작업 큐를 두지 않는다.

## Verification

- 짧은 영어 파일(문장 3~5개)로 실제 앱에서 확인: 업로드 → 좌측에 영어 문장별 행,
  우측 빈 칸 → "번역 시작" → 우측이 위에서부터 채워지고 진행률이 오른다 → "정지"가
  즉시 먹고 그때까지가 화면에 남는다.
- `~/Downloads/test.txt`로 확인: 긴 문서에서도 진행률이 오르고 정지가 동작한다.
  (전체 완주는 시간·차단 때문에 필수 아님. 부분 진행 확인으로 충분.)
- 영어 마커가 없는 파일 → 안내문이 뜨고 문서가 생기지 않는다.
- 번역된 문서를 브라우저 인쇄 미리보기로 열어 A4 2열·매 쪽 머리말을 확인한다.
- `bun run test`(문장 분리·파싱 단위 테스트) 통과. `bun run test:e2e`(업로드, 정지,
  형식 오류 경로) 통과.
